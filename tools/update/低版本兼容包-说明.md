# 低版本兼容包（给 Android 15 以下的老设备）

## 这是什么

主线 APK 的 `minSdk` 是 **35**，意思是「只允许 Android 15 及以上安装」。
Android 15 以下的老手机/平板（例如鸿蒙 4.x 平板，底层约 Android 12）装上会报：

```
解析包时出现问题。
```

**兼容包**就是把 `minSdk` 放宽到 **26（Android 8.0）** 的同一份程序，
功能和主线完全一致，只是能在老设备上装进去。

> 兼容包**只用来单独发给老设备的学生**，不放进 Gitee 发行版、不进更新清单，
> 主线版本（现有用户的自动更新通道）完全不受影响。

## 打包命令

项目里没有 gradlew，用的是安装好的 Gradle。加 `-PlegacyCompat` 就是打兼容包：

```bash
cd D:\AndroidProjects\CollocationMemory
set JAVA_HOME=C:\Program Files\Android\Android Studio\jbr
C:\Users\王佳豪\.gradle\wrapper\dists\gradle-8.4-bin\cnqr4qbc93ir6sp626e40kx2s\gradle-8.4\bin\gradle.bat assembleRelease -PlegacyCompat
```

产物：`app\build\outputs\apk\release\app-release.apk`
（复制出来改名成 `CollocationMemory-<版本>-兼容版.apk` 再发给学生）

不带 `-PlegacyCompat` 就是正常的 main 线打包，行为与以前完全一样。

## 两个包的区别

| | 主线包 | 兼容包 |
|---|---|---|
| minSdk | 35（Android 15+） | **26（Android 8.0+）** |
| versionCode | 30 | 30（**同号**） |
| versionName | 3.9 | 3.9-兼容版 |
| 签名 | 7742553b… | 7742553b…（同一个签名） |
| 体积 | 20.7 MB | 9.2 MB（dex 压缩方式不同，内容一致） |
| 分发方式 | Gitee 发行版 + 群 | **只在群里单独发** |

**versionCode 相同**是有意设计的：

- 兼容包用户不会收到「发现新版本」的弹窗（App 判定 30 ≤ 30 = 已是最新）；
- 反过来，主线用户也不会被兼容包打扰。

代价是：以后主线发 4.0（versionCode 31）时，兼容包用户的 App 会提示更新到 4.0，
而 4.0 主线包装不上老设备。**所以那时要给老设备再打一个 4.0 兼容包**，
并且只把兼容包发给他们（不要让他们点 App 里的更新弹窗）。

## 兼容版的词库热更新：照常自动生效

两条通道是独立判定的（`MainViewModel.silentUpdateCheck` 里 `appDue` / `libraryDue` 分开算）：

| 通道 | 主线包 | 兼容包 |
|---|---|---|
| **词库 / 释义热更新** | ✅ 自动（启动后限流 30 分钟） | ✅ **同样自动**，机制完全一样 |
| 整包更新（换 APK） | ✅ 启动弹窗提示（限流 6 小时） | ❌ 判定「已是最新」（versionCode 相同），不提示 |

所以：**以后加词、改释义、删错词，兼容版学生打开 App 就自动收到，不用换包。**
只有改动界面/代码时才需要重新打一个兼容包单独发给他们。

原理：词库更新比的是清单里 `library.version`，与 App 自身的版本号无关；
`evaluateAppUpdate` 返回「已是最新」并不影响 `syncLibrary` 继续执行。

## 学生怎么装（发给学生的原话）

> 不好意思，之前那个安装包在你的平板上装不了，是我的问题。
> 请用下面这个「兼容版」重新装一下：
>
> 1. 先在文件里找到上次下载的那个 `CollocationMemory-3.8-release.apk`，**删掉**（避免装错）
> 2. 下载群里新发的 `CollocationMemory-3.9-兼容版.apk`（约 9 MB，比上一个小很多，能看出对不对）
> 3. 下完直接点它安装，如果提示「允许安装未知应用」，允许一下即可
> 4. 装好后打开是「设置 → 关于」能看到版本号 `3.9-兼容版`
>
> 学习记录不受影响；以后更新会自己在软件里提示。

## 报错对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 解析包时出现问题 | 用了老的主线包（minSdk 35）；或文件没下完整 | 改用兼容包；核对文件大小 9.2 MB 左右 |
| 文件打开失败（QQ 浏览器里） | QQ 浏览器的预览器不认 APK | 正常现象，用「文件管理」找到文件点开安装，别用浏览器打开 |
| 应用未安装 / 签名不一致 | 装过不同签名的包 | 卸载旧的（会清数据，先确认）再装 |
| 提示「已存在更高版本」 | 装过主线 3.9（同 versionCode） | 可直接覆盖安装 |

## 已知提醒

- 兼容包的签名校验：Android 9 以下没有签名证书 API，`ApkInstaller` 会自动跳过证书比对
  （下载前的大小 + SHA-256 校验仍在，安全性不降级）。见 `ApkInstaller.verifySameApp`。
- 兼容包**不要**上传到 Gitee 发行版，也不要让 `make_manifest.py` 把它写进清单。
  清单必须始终指向主线包，否则所有用户都会被推去装兼容包。
